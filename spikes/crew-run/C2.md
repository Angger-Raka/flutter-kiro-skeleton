# C2 — Tactile spike (S15, S16, S17, S19)
- Date: 2026-11-17
- Results:
  - S15: `SpringDescription.withDurationAndBounce(duration: 400 ms, bounce: 0.12)` compiles on Flutter 3.44.8 (Dart 3.12.2) and settles at 1. It gives mass 1, stiffness 246.74, damping 27.65, identical to the fallback formula in 04 §8. Decision: plan kept (use the constructor; kit does not need to generate springs).
  - S16: The 04 §4.5 conversion `max(0, (cssBlur/2 - 0.5) / 0.57735)` was used untuned. The user compared goldens with `web_reference.html` at 400 % zoom in Chrome: rings, drops and 0.5 px hairlines look the same, light and dark. Decision: plan kept, constant 0.57735 and offset 0.5 unchanged (exposed as `kBlurK` and `kBlurOffset` in `lib/tactile.dart`). No numeric pixel diff was run.
  - S17: Tab order, Enter and Space, semantics labels, `androidTapTargetGuideline` and `labeledTapTargetGuideline` pass in widget tests; the user confirmed press scale, focus ring, keyboard use in Chrome, and VoiceOver reads the button labels. Note: a 48 px hit area around a 36 px visual only works if the layout is padded to 48 on touch (`MinHitArea` render object), because a hit area outside the parent's layout size is never hit-tested. Decision: plan kept, with that layout cost on touch.
  - S19: `BackdropFilter` with sigma 2 over a black 30 % (light) / 90 % (dark) backdrop, with a looping animation behind it. The user saw no stutter in Chrome. Decision: plan kept.
- Defects found by the user in Chrome, and fixes:
  1. Every Text had a double yellow underline (Flutter's debug marker for Text with no Material or DefaultTextStyle above it). Cause: `MaterialApp.home` was a bare `Stack`. Fix at the root: `home` is now a `Scaffold`. Regression test: `app root: no debug underline, whole window follows the theme`.
  2. In dark mode the top strip with "Light mode" and "Blur" stayed white. Fix: the strip is a 56 px row inside the same ground-coloured `Scaffold`, so the whole window follows the theme (#F9F9F8 light, #080807 dark).
  3. Self-check against tokens.md found no other deviation. Goldens were never affected (they already used a `Scaffold`) and were regenerated.
  After the fixes the user re-checked in Chrome: underline gone, strip follows dark mode, VoiceOver reads labels, no blur stutter, goldens match the browser reference.
