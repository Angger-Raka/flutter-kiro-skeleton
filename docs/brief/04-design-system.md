# 04 — Design system: tactile-design for Flutter

## 0. Summary

The skeleton's visual language is **tactile-design** by Kosta / 4hands
([site](https://www.4hands.dev/tactile-design), [repo](https://github.com/kosta4a/tactile-design), MIT license),
adapted from web (CSS/Tailwind) to Flutter.

The language in five lines:
- Controls look like physical objects. Secondary actions are white and raised with a fine ring and a crisp 1px drop, the one primary action is the ink-12 fill, and fields are sunk wells.
- Every surface takes its fill, edge, and drop from the surface underneath it, so a control looks equally pressable on a page, card, rail, sheet, or row, in light and dark.
- Hierarchy comes from a size step plus an ink step, with one font weight. Never bold, never colour.
- Hue only carries meaning (status or identity), never importance.
- Motion is short, starts at once, has one purpose, and has a reduced-motion version.

Why it is the default: without a system, agents fall back on generic defaults (a coloured button everywhere, bold
headings, big soft shadows, random spacing) and every screen looks like generic AI output. tactile-design gives the
agent a decision order, concrete roles, and exact values, and `kit` enforces them.

This document adds three things on top of the upstream skill:
1. How every tactile role becomes a Flutter token, theme value, or core widget (§4–§9).
2. Where this project deviates and why (§2).
3. What `kit` computes and checks, so agents never translate CSS by hand (§4, `05-kit-cli.md`).

## 2. Deviations from the upstream skill

| Topic | Upstream (web) | This project (Flutter) | Why |
|---|---|---|---|
| Size classes | phone < 768 px, otherwise desktop | mobile < 768, tablet 768–1199, desktop ≥ 1200 (§3). Tablet uses the desktop size and type set | User wants Mobile/Tablet/Desktop; the mobile boundary equals tactile's phone boundary |
| Touch rules | `(pointer: coarse)` media query | `InputMode.touch` when `defaultTargetPlatform` is iOS or Android (also on web), otherwise `pointer` | Flutter has no coarse-pointer query; the platform is the reliable proxy |
| Hit area | 44 pt | **48 × 48** on touch; visual sizes stay tactile (44 controls on mobile, small icons keep their look) | Android accessibility guideline; covers Apple's 44 pt |
| Phone navigation | top bar + menu panel | **bottom tab bar** for 2–5 destinations, tactile-styled (§7, shell). Menu panel only above 5 destinations | iOS/Android convention for top-level app navigation |
| Press feedback | CSS `scale` on `:active` | `Pressable` scales. Material ink ripples are off app-wide (`NoSplash.splashFactory`) | Ripples are not part of the language |
| Hover | gated to fine pointers | Flutter reports hover only for mice. On touch, `Pressable` shows the hover fill while pressed | Same result, no gating code |
| Shadows | CSS `box-shadow` | `BoxShadow` lists generated by kit, blur converted (§4.5) | CSS blur ≠ Flutter `blurRadius` |
| Springs | `{ bounce, duration }` in a motion library | `SpringDescription` built from the same two numbers (§8) | Same parameters, Flutter physics |
| Font fitting | `font-size-adjust` | type sizes multiplied by a per-face factor (§6.2) | Flutter has no `font-size-adjust` |
| Icons | Lucide, 1.5 px stroke | Lucide through `lucide_icons_flutter`, class `LucideIcons300` (S23); fallback Material Symbols Rounded at weight 300 | Closest available match |
| Toast | custom pill | `AppToast` overlay, not `SnackBar` | `SnackBar` cannot hug its content |
| Charts | bar/line guidance | `AppBarChart` (simple bars, no chart package) | Lean skeleton; tactile prefers bars |
| Tables, switch, menus, status dots | full specs | not in MVP (`AppTable`, `AppSwitch`, `AppMenu`, `StatusDot` are stretch) | Not needed by Orbit or Tally |
| Copy rules | in markup | enforced in ARB files for every locale (TAC007, TAC008) | Strings live in l10n |

Material widgets stay as **infrastructure** (routes, text input, semantics, scrolling, tooltips, selection).
Their visuals are overridden by the theme (§9). Where Material cannot express tactile (press scale, crisp
multi-layer shadows, surface-relative fills, sliding pill), a custom core widget is used.

## 4. Tokens

### 4.1 The knobs (`design/tokens.yaml`)

Only brand decisions are configurable. Everything else (heights, hairline, shadow geometry, durations,
spacing ladder, curves) is the tactile system and stays fixed unless overridden on purpose.

```yaml
version: 2
language: tactile-design@30495a2
neutral: sand              # Radix neutral: gray | mauve | slate | sage | olive | sand | custom
# custom_neutral: { light: [12 hex], dark: [12 hex], alpha: { a3: hex, a4: hex } }
surface_top: "#ffffff"     # top surface in light mode
hues:                      # Radix hue names, or custom { light: [12], dark: [12] }
  accent: blue             # the brand hue; only where it means the brand itself
  success: green
  danger: red
  warning: amber
  info: blue
  identity: [cyan, violet, plum, pink, lime, purple]   # categories, tiers; kit rejects hues within 25° of a status hue
primary: neutral           # neutral (ink-12 fill, default) | accent (opt-in brand primary)
# theme mode is a user setting (AppSettings, default: system), not a token
typography:
  sans: { family: Inter, files: [assets/fonts/Inter-Medium.ttf], weight: 500 }
  heading: null            # optional brand face: display + section titles only, one weight
  mono: null               # null = platform monospace
  size_factor: 1.0         # 1.0 for Inter; other faces see §6.2
  tracking: { label: -0.01, display: -0.02 }   # em; use 0 for tightly spaced faces
radius_control: 6          # 4–8, match the icon set; the radius ladder follows
contrast:
  tune_faint_text: true    # kit adjusts ink-9/ink-10 until the gates pass (§4.6)
overrides: {}              # deliberate changes to system values; kit tokens lists each one
```

### 4.3 Colour data

`kit` contains `tool/kit/lib/src/data/radix_colors.g.dart`, generated by `tool/kit/tool/fetch_radix.dart` from
`radix-ui/colors` (`src/light.ts`, `src/dark.ts`) at commit `dbdb854` (MIT). **No colour value is typed by hand.**
Text on a hue-9 solid ("contrast" colour) is white, except for sky, mint, lime, yellow, and amber, which use the
neutral's ink-12.

### 4.4 Derived values (computed by kit)

| Value | Rule |
|---|---|
| Dark ground | dark ink-1 with OKLCH lightness −0.04, same hue and chroma |
| Primary hover | OKLab mix: 93 % primary bg + 7 % primary fg |
| Dark badge edge | 34 % of the badge's hue-11 mixed into black |
| Alpha steps (custom neutral) | ink-12 at 6 % / 10 % (light), 7 % / 11 % (dark) |
| Surface remaps, per-surface outlines | §5 |
| Brand/status collision | a brand hue within 25° (OKLCH hue) of a status hue becomes that status's scale |
| Identity validity | identity hues within 25° of any status hue are rejected (TAC010) |

OKLCH hues of the Radix step-9 colours, computed on 13 Nov 2026: red 23°, amber 84°, green 158°, jade 171°,
blue 252°. With the default status hues (red, amber, green, blue), valid identity hues include cyan (30° from blue),
violet, plum, pink, lime, and purple. Teal (24° from green), orange (22° from red), brown and gold (near amber),
tomato, ruby, crimson, indigo, mint, grass, and yellow are rejected.

### 4.5 Shadow conversion

Recipes are stored in CSS notation inside kit (x, y, blur, spread, colour) and converted when generating Dart.
Offsets and spread carry over unchanged. Blur needs conversion because CSS uses a Gaussian sigma of `blur / 2`,
while Flutter turns `blurRadius` into sigma as `r × 0.57735 + 0.5`:

```
flutterBlurRadius = max(0, (cssBlur / 2 − 0.5) / 0.57735)
```

Rings are zero-blur spread shadows (`BoxShadow(spreadRadius: 1)`). **[VERIFY S16]** with a golden next to a
browser screenshot of the same recipe.

### 4.6 Contrast gates

`kit tokens` exits non-zero if a gate fails (TAC009). Gates (WCAG ratio, both themes unless noted):

| Pair | Minimum |
|---|---|
| ink-12 on ink-1, ink-2, ink-3 | 7 : 1 |
| ink-11 on ink-3 | 4.5 : 1 |
| ink-10 on ink-1 (only if used for meta and labels) | 4.5 : 1, otherwise 3 : 1 for icons and placeholders |
| ink-9 (icons and non-essential text only) | 3 : 1 |
| hue-11 on hue-3 | 4.5 : 1 |
| ink-6 hairline vs surface top | 1.35 : 1 |
| focus ring (ink-10) on surface top, ink-3, dark ink-1…4 | 3 : 1 |
| accent primary text (if `primary: accent`) | 4.5 : 1 |

Default Radix sand fails the ink-10 meta gate (3.87 : 1 on white). With `tune_faint_text: true`, kit shifts ink-9
and ink-10 in OKLCH lightness until they pass and reports the change. With `false`, the text roles that must pass
4.5 : 1 (meta, figure labels, empty-state lines) automatically use ink-11.

## 5. Surfaces: the step-shift rule in Flutter

`lib/core/theme/tactile/surface.dart`:

- `enum SurfaceKind { ground, rail, panel, raised, overlay, sheet, well }`
- `TactileSurface(kind:, radius:, padding:, child:)` paints its fill, edge, and drop relative to the parent
  scope, then provides a new `SurfaceScope` to its descendants.
- `SurfaceScope` (an `InheritedWidget`) exposes: working ink steps 1–7 for that surface, `line`, hover and
  selected fills, and resolved shadow lists for controls placed on it (`button`, `primary`, `toggle`, `badge(hue)`).
- Core widgets read `context.surface`, never absolute colours. That is how one `AppButton.secondary`
  is correct on a panel, card, rail, sheet, or row, in both themes.
- Text steps 8–12 never remap, so text ink is identical everywhere.

Light mode remap (working step ← root step):

| Surface | ink-1 | ink-2 | ink-3 … ink-7 |
|---|---|---|---|
| rail (on the ink-2 ground) | root 2 | root 3 | root +1 each |
| panel | surface top | root 2 | root |
| overlay, sheet | surface top | surface top | root |
| raised | root | root | root |

Dark mode: steps stay root. Fills step up instead: a card is its parent + 1 step, a control is its parent + 2.
Each surface redeclares the control outline three steps above the control fill: on the panel ink-6 (control
fill ink-3); on raised, overlay, and sheet surfaces ink-7 (control fill ink-4). Every dark edge is one solid 0.5 px
outline plus a tight black drop, never a lit top edge and never a light-coloured shadow.

Hover = local ground + 1 step, selected = local ground + 2 steps, so hover never matches selected.

Switching theme changes only colours and shadows. Sizes, padding, radii, and stroke widths are theme-independent
by construction (theme-specific tokens contain only colours and shadows).

## 6. Typography

### 6.1 Roles

One weight for every role (`typography.sans.weight`). `FontWeight.w600` and heavier are banned outside
`core/theme/` (TAC002). Line heights are absolute: Flutter `height = lineHeight / fontSize`, with
`leadingDistribution: TextLeadingDistribution.even`.

| `context.text.*` | Desktop + tablet | Mobile | Ink | Material `TextTheme` slots |
|---|---|---|---|---|
| `display` | 32/40, −0.02 em | 32/40 (24/32 when it wraps past 2 lines) | 12 | displayLarge/Medium/Small, headlineLarge |
| `figure` | 24/32, tabular | 24/32 | 12 | headlineSmall |
| `section` | 20/28 | 20/28 | 12 | headlineMedium, titleLarge |
| `title` | 16/24 | 16/24 | 12 | titleMedium |
| `body` | 13/20 | 15/24 | 12 | bodyLarge, bodyMedium, titleSmall |
| `description` | 13/20 | 14/20 | 11 | — |
| `meta` | 12/16 | 15/20 (14/20 under a larger lead) | 10, or 11 if the gate fails | bodySmall, labelSmall |
| `label` (buttons) | 13/20, −0.01 em | 15/24 | per control | labelLarge, labelMedium |
| `field` | 13/20 pointer · 16/24 touch | 16/24 | 12 | input text |
| `badge` | 12/20 | 14/22 | hue-11 | — |

- A heading face (if set) applies to `display` and `section` only. Never to controls, badges, or body text.
- Tabular figures (`FontFeature.tabularFigures()`) on `figure`, amounts, and any column of numbers.
- Ellipsis is always the "…" glyph (Flutter's `TextOverflow.ellipsis` uses it).

### 6.2 Typeface fit

The scale is tuned for Inter, whose x-height is 0.546 of its em. For another face:
1. **Size.** Multiply every size by `0.546 / (xHeight / unitsPerEm)`, round to 0.5, keep line heights on the 4 px grid.
   MVP: set `size_factor` by hand after a side-by-side golden. Stretch: `kit fonts measure <ttf>` reads the OS/2 table.
2. **Weight.** Render the same 13 px string in Inter 500 and in the face at 400/500/600; pick the closest ink coverage.
   Ship only that static weight. Never a synthesised weight.
3. **Tracking.** Keep −0.01/−0.02 em only for faces as loosely spaced as Inter.
4. **Requirements.** Tabular figures and a real ellipsis glyph.

## 8. Motion

| Token | Value | Use |
|---|---|---|
| `AppMotion.easeOut` | `Cubic(0.23, 1, 0.32, 1)` | default for anything the user caused, hover and colour included |
| `AppMotion.easeMove` | `Cubic(0.22, 1, 0.36, 1)` | long moves of big objects (400–450 ms) |
| `AppMotion.easeDrawer` | `Cubic(0.32, 0.72, 0, 1)` | a sheet after release: spring back 400 ms, slide out 300 ms |
| `AppMotion.easeInOut` | `Cubic(0.77, 0, 0.175, 1)` | one-off fold where both ends stay on screen |
| Durations | 80 silent fade · 120 small exit · 150 press/hover/menu in · 200 swap/exit/overlay · 240 modal in · 300 sections/height · 320 sheet up | `AppMotion.d150`, … |
| `AppSprings.toggle` | bounce 0.12, 0.4 s | segmented pill |
| `AppSprings.knob` | bounce 0.2, 0.45 s | switch knob |
| `AppSprings.reveal` | bounce 0.2, 0.35 s | height reveals |

Springs: use `SpringDescription.withDurationAndBounce` if the pinned Flutter has it **[VERIFY S15]**; otherwise kit
generates `mass 1, stiffness (2π / d)², damping 4π(1 − bounce) / d`.

Rules:
- Decide whether to animate before how. Constant actions (typing, scrolling, hover) get colour or opacity ≤ 150 ms.
  Keyboard actions, drag, resize, and data figures never animate.
- Transform and opacity only; blur only as a short bridge (label swaps 2 px, modal 4 px).
- Exits are faster than entrances. Nothing enters from scale 0; menus and modals from .95–.97.
- Never `Curves.easeIn*` (TAC004). Literal `Duration(...)` in widget code is banned (TAC005); use `AppMotion`.
- Implemented once in core: press scale, per-row hover fade, modal (16 px rise + 4 px blur + fade, 240 in / 200 out),
  sheet, label swap (±6 px, 2 px blur, 200 ms), copy tick, page entrance (fade + 16 px rise, 300 ms, route mount only,
  through `PageTransitionsTheme`).
- Reduced motion: `MediaQuery.disableAnimationsOf(context)` (exposed as `context.reduceMotion`). Travel, blur, and
  scale become 150–200 ms crossfades; the knob moves instantly; press scale may stay. Every core animation honours it.

## 10. Layout, data, and copy rules (summary for agents)

**Rhythm:** section title 20/28 → 6 → description → 24 → content; 32 above and below sections; 20 between form fields;
card padding 24 (20 on mobile); title-to-description gaps 2 (card title), 4 (page title in chrome), 6 (section),
8 (display). Nudges move in 1, 2, or 4; blocks in 8, 16, or 32.

**Amount of data:** summary lists stop at 5–6 rows, then "View all" or a pager; full list pages load 20 at a time;
prefer one strong figure over many small ones; hide empty, finished, or irrelevant sections; never show fake data.

**Placement:** actions sit above the data they act on (right of the section title); paging sits below, outside the
card; a control sits next to what it sets; filters stay on one row (mobile: horizontal scroll with 20 px edge
fades, never wrap); search sits at the right of the filter row (mobile: first, full width).

**Proportion:** siblings share height, padding, radius, and text size; padding equal on all sides of bars and
cards; one left edge per column; values set against labels align right (outside tables); media 16:9; nested
radius = outer radius − border; no double borders; 0.5 px is the only structural line weight.

**Copy:** sentence case; buttons are verb + object ("Create budget"); a confirm names the action ("Yes, delete");
loading labels end with "…"; no em dashes; no eyebrow labels above titles; descriptions explain the mechanism
instead of restating the title; shorter wording on mobile. Applies to every locale (en, id). Checked by TAC007 and
TAC008.

## 11. UI resilience (`ui-resilience.md`)

1. `Text` inside a `Row` is wrapped in `Expanded`/`Flexible`. Titles clamp at 2 lines, card descriptions at 2 lines;
   one-line free text (names, URLs) truncates past ~32 characters with a tooltip holding the full value.
2. No fixed heights on containers that hold text. Use minimum heights.
3. Content that can exceed the viewport scrolls. No long `Column` without a scroll view.
4. Images have a fixed size or `AspectRatio` (16:9 for media), a placeholder, a 0.5 px frame, and an error fallback
   that looks intentional (ink-2 fill, an 18 px image icon in ink-9). Expect the fallback often: some sites block image
   requests. On web, `AppNetworkImage` uses `Image.network`, which falls back to an `<img>` element for images served
   without CORS **[VERIFY S24]**.
5. Lists of unknown length use builders.
6. Numbers, money, and dates go through `core/utils` formatters (intl): whole amounts drop decimals; values over
   6 digits use compact notation (1,2 jt / 1.2M) with the full value in a tooltip; missing values show an ink-9
   en dash; plurals use intl plural rules.
7. Button labels never wrap. Desktop buttons hug their labels; mobile stacks fill the width; shorten copy rather than wrap.
8. Filter rows scroll horizontally on one line. Tag groups inside content may use `Wrap`.
9. Forms scroll and respect `MediaQuery.viewInsets`.
10. `SafeArea` on mobile; `PageColumn` on wide screens.
11. Layout stability: swapping states share one cell sized to the larger state; loading keeps the layout; nothing
    jumps when data or a label arrives.
12. Long, empty, emoji, RTL, and very large values never break layout (stress tests).

## 12. Stress tests, accessibility checks, and goldens

**Stress tests** (`test/helpers/stress.dart`) render a widget across sizes, text scales, themes, input modes, and
fixtures. Any `FlutterError` (including `RenderFlex overflowed`) fails the test; test names include the combination.

| Profile | When | Matrix | Renders per widget |
|---|---|---|---|
| `quick` (default) | local runs, agent loops, before each commit | 320×640 @ 2.0 touch and 1600×900 @ 1.0 pointer, light, all fixtures; plus 375×812 @ 1.0 dark with `normal` | 17 |
| `full` | CI and before release | sizes 320×640, 375×812, 768×1024, 1024×768, 1200×800, 1600×900 × text scales 1.0, 1.5, 2.0 × light and dark × pointer and touch (for widgets whose sizes depend on it) × all fixtures | 288–576 |

Select the profile with `flutter test --dart-define=STRESS=full`. Fixtures: `normal`, `long` (60 words), `longWord`
(80 characters, no spaces), `empty`, `emoji`, `rtl`, `bigNumber` (9 digits), `nullValue`. `stressProperty`
(property-based) generates random strings and numbers for fixture fields with a fixed CI seed.

**Accessibility checks** run inside the quick profile at 375×812, light and dark, with the `flutter_test` guideline
matchers `androidTapTargetGuideline` (48 × 48), `labeledTapTargetGuideline`, and `textContrastGuideline`. A test may
skip the contrast check only with a written reason (for example, text over an image).

**Goldens** (tag `golden`):
- Every core widget at its own size; every page view at mobile 390×844, tablet 834×1194, and desktop 1440×900; light
  and dark; `devicePixelRatio = 2` so 0.5 px hairlines show; fonts bundled and loaded in the test with `FontLoader`
  (otherwise `flutter test` draws Ahem); `ThemeData.platform = macOS` so layout is pointer mode (36 px), because tests
  default to Android (touch, 48 px).
- Generated and compared on the developer's Mac only, because font rendering differs between macOS and Linux.
  `flutter test --tags golden --update-goldens` creates or updates them; `flutter test --tags golden` compares.
  CI runs `--exclude-tags golden`. Stretch: compare on a GitHub macOS runner if S9 shows identical output.
- At least one test pumps the real app root, not a widget wrapped in a `Scaffold`; a wrapper hides a missing Material
  ancestor (yellow debug underlines).
- Goldens are committed. `SCREENS.md` links them, and the `ui-reviewer` agent reviews them against the skill's
  "never ship" list plus §2 of this document.
